# 原生账户用户指南

> 中文版本与 `docs/NATIVE_ACCOUNT_USER_GUIDE.md` 同构。若两者冲突，以英文版本为准。

原生 SmartAccount 是草案协议。请使用已显式激活匹配配置、并能完成原生发现的节点。外部评审、公开网络激活与生产部署仍是彼此独立的决策。选择某个公开 RPC 端点不会激活该服务。

## 初始化并保管好正确的备份

| 项目 | 用途 | 需要保留什么 |
| --- | --- | --- |
| 账户 ID | 标识账户及其设置 | 网络与账户 ID |
| 资金地址 | 持有账户资产 | 注册后展示的、经独立核验的地址 |
| 公开恢复描述符 | 记录原始托管、盐值、身份、资金地址与配置 | 一份可用于查找并核验账户的副本 |
| 托管钱包备份 | 授权管理与默认执行 | 钱包私钥或恢复备份，妥善保管 |
| 守护者钱包备份 | 授权紧急冻结与托管恢复 | 与托管分离、独立控制的另一份安全备份 |

描述符不含私钥。它无法签名、无法恢复丢失的钱包密钥，也无法移除守护者。托管恢复之后，其原始身份字段仍标识同一账户；新的链上状态展示当前托管。绝不要把私钥写进描述符或经审阅的请求中。

在[原生工作台](NATIVE_ACCOUNT_WORKSPACE.md) 中，先核验网络与节点，然后为托管选择一个受支持的 Neo 钱包权限方，并为守护者选择另一个独立控制的权限方。审阅推导出的账户 ID 与独立的资金地址，在同一笔交易中取得托管与守护者的同意见证，确认注册，并在充值之前读取已记录的账户状态。向账户的资金地址充值。请把钱包备份与公开描述符分开保管。[SDK 指南](NATIVE_SDK.md) 描述了受支持的签名接口与确切的交易审阅方式。

## 谁能行动，以及何时

守护者是账户配置的恢复权限方。每个操作都需要一个交易费用支付方；付费不会授予账户权限。当支付方控制所需钱包时，它也可以同时充当托管或守护者。

| 变更 | 谁发起 | 谁完成，何时 | 待生效期间谁能取消 |
| --- | --- | --- | --- |
| 替换或移除验证器 / 钩子 | 托管，账户处于 Active 且没有待生效的托管恢复 | 24 小时之后由任意支付方完成；账户仍须满足这些状态条件 | 托管，包括成熟之后、激活执行之前 |
| 变更模块策略，包括会话密钥 | 托管，账户处于 Active 且没有待生效的托管恢复 | 托管在 24 小时之后重复完全相同的已存储调用 | 托管；选择验证器或钩子角色并审阅其待生效调用 |
| 变更守护者 | 托管与新指定的非零守护者，账户处于 Active 且没有待生效的托管恢复 | 24 小时之后由任意支付方完成 | 待生效期间由托管取消 |
| 将托管恢复到新钱包 | 已配置的守护者与拟定的托管钱包，账户处于 Active 或 Frozen | 七天之后由任意支付方完成 | 待生效期间守护者可随时取消；托管只能在成熟之前取消 |
| 冻结 | 已配置的守护者，账户处于 Active | 交易执行时生效；没有协议等待期 | 不存在待生效提案；恢复使用需要解冻 |
| 解冻 | 托管与已配置的守护者共同参与 | 交易执行时生效；没有协议等待期 | 不存在待生效提案 |

当某个权限方相对于当前托管、恢复与待生效权限地址是首次引入时，会检查其同意。对已准入的待生效地址重新提案不需要新的接收方同意；但当前控制权限的检查仍然适用。

已成熟的激活会应用其执行时存在的已授权意图；其支付方无法在激活调用中选择替换对象。模块替换仍然需要有效的模块代码与成功的清理。模块策略的应用是另一项操作，需要托管再次参与。在激活或取消之前，请检查当前的待生效载荷。取消策略提案不会撤销当前活跃的策略。

在工作台中，行动之前请刷新账户与链时间。对于策略调用，选择其验证器 / 钩子角色，刷新待生效策略，检查已存储的参数，然后选择取消或激活审阅。快照不会在另一笔交易改变账户时自动更新。重新校验会拒绝它观察到的变化。SDK 的策略取消交易还会在取消之前立即在链上比对经审阅的完整待生效内容。若内容已改变或消失，交易会失败，而不是取消另一个提案。请使用完整的导出脚本：普通钱包的方法调用无法保留这一检查。在同一区块内重建的、完全相同的记录仍会匹配；不存在唯一的提案实例编号。其他激活与恢复调用在执行时作用于它们当时的待生效状态。请协调托管设备，并检查已确认的账户与待生效策略状态。

截止时间与延迟使用**链上时间（毫秒）**，而不是你的设备时钟。操作在其确切截止时间仍然有效；意图在其确切成熟时间成熟。托管的恢复取消权在那一刻终止。一笔被打包进更晚区块的交易可能在预览成功之后仍然错过其截止时间。反向推进的转换会使其他待生效配置失效；每次后续操作之前都要重新加载状态。

## 紧急遏制与守护者信任

移除或变更会话密钥是延迟的。活跃的密钥可以持续行使其既有权限，直到它过期或账户被冻结。需要立即遏制时，请让守护者**先冻结**，确认 Frozen 状态，然后**再发起恢复**（如果托管需要更换）。

冻结会清除**所有待生效意图**，包括恢复、验证器 / 钩子变更、守护者变更与模块策略调用。因此在提出恢复之后冻结，会取消该恢复提案。仅提出恢复并不会冻结一个 Active 账户。

恢复会保留账户 ID、资金地址、操作 nonce 通道、守护者与 Frozen 状态。它替换托管，并在不调用旧模块的情况下摘除旧验证器与钩子。解冻仍然需要新的托管与已配置的守护者。Frozen 账户必须先解冻，才能进行新的模块配置。一旦回到 Active，托管可以使用默认执行，而新策略遵循其常规激活延迟。

请选择一个你信任其持续可用并愿意配合的守护者。它可以在没有托管参与的情况下冻结账户，而在已配置守护者时，托管无法单独解冻。若守护者密钥在 Frozen 期间丢失，本配置没有仅托管的豁免。恢复不会移除或替换守护者。在 Active 且没有待生效托管恢复时，托管可以提出守护者替换，需 24 小时延迟；该待生效变更同样会被冻结清除。

标准 Neo 阈值多签钱包可以作为守护者。例如，独立备份的 2-of-3 密钥可以容忍一把密钥不可用，其余两把仍能授权守护者。这是一个带有阈值见证的守护者地址，与账户的验证器模块相互独立。托管仍必须参与解冻。若 Frozen 期间可用密钥少于阈值，则没有豁免；阈值恢复降低了单把密钥失效的风险，但在所有可用备份都丢失之后并不会创造新的权限。

## 若密钥或备份丢失

| 情况 | 可用路径 |
| --- | --- |
| 托管密钥丢失，守护者可用 | 守护者提出恢复到新的托管钱包，七天之后完成。若旧密钥可能已泄露，请先冻结。 |
| 守护者密钥丢失，账户 Active 且托管可用 | 在没有待生效托管恢复的前提下，托管可以提出新的守护者，并在 24 小时之后激活。 |
| 守护者密钥丢失，账户 Frozen | 从其备份恢复守护者钱包。托管恢复无法绕过解冻所需的守护者。 |
| 会话密钥丢失或泄露，托管可用 | 审阅延迟的替换 / 移除操作。如有必要，使用守护者冻结进行即时遏制。 |
| 描述符丢失，钱包密钥可用 | 从你的记录中找回已知的网络 / 账户 ID，并在链上核验状态。钱包备份与描述符承担不同用途。 |
| 托管密钥丢失，且没有可用守护者 | 本配置没有密钥恢复捷径。已配置的验证器可能仍允许其自身的操作，但不会在管理事务上替代托管。 |

## 费用、结果与不确定的提交

签名之前，请审阅确切的目标、参数、截止时间、权限方以及系统 / 网络 / 总费用上限。原生账户本身不能作为费用支付方。由外部支付方签署完整交易并支付其费用。工作台的消耗估算与最小预算预览不是最终交易报价；请通过钱包或 SDK 审阅最终网络费用与总额。

一笔以 Application FAULT 提交的交易仍可能向支付方收费；回滚应用层变更不会退还交易费用。目标返回 Boolean `false` 属于业务结果，本身不是 VM 错误。适用的模块可能会拒绝它；SDK 会拒绝 `transfer` 结果中除 Boolean `true` 之外的一切。请检查实际回执以及随之产生的余额、nonce 与策略。

返回交易 ID 意味着已提交，而不是已确认。若请求超时，请查询**同一个交易 ID** 并检查钱包的提交情况，然后再准备替代交易。不要自动签署另一笔交易或提高费用。成功的预览既不预留 nonce，也不保证在区块中占据位置。
