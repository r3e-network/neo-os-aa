# 原生组合验证器配置档

## 目的与兼容性

把异构 MultiSigVerifier 策略适配到 SmartAccount 原生合约，同时不削弱回调阶段隔离。这是模块配置档，不是对原生共识激活、回调预算或操作字节的更改。旧版工件保持独立。原生兼容性需要全新的模块部署与绑定；它不是就地升级旧版。当前原生配置档要求 ABI 2，以及 `SMARTACCOUNT-NATIVE-MODULE-PROFILES.md` 中规定的带标记权威代次存储命名空间。在恢复后重新存入同一模块或子级密钥，不会恢复旧策略状态或签名。

## 接口与状态

原生清单显式声明 `compositeVerifier: true` 与确切的配置档参数摘要。准入要求非 safe 回调 `validateCompositeSignature(Hash160, Array) -> Array` 与 `postExecuteComposite(Hash160, Array, Any, Array) -> Void`。普通叶子验证器保留 Boolean 校验与三参数后置执行。

唯一的根配置能力是 `setConfig(accountId, children, threshold)`。候选有界配置档允许一到三个有序、唯一、非零的叶子验证器，且排除根自身；threshold 为一或二，且不得超过名册长度。聚合最多包含三个互不相同的 32 字节签名方域。根与子级的重新配置必须原子地重新检查这些边界。实际的 VM 最坏情况测量仍是发布门禁；声明或一次小型成功操作不能确立支持。

域承诺为 `SHA256(StdLib.Serialize([threshold, orderedChildren, perChildDomainArrays]))`。每个子级边界与子级顺序都被保留。回复必须是确切的 Array，包含不可变的 32 字节 ByteString。Struct、Buffer、重复域、空集或超限集都会被拒绝。根在调用下一个子级之前持有返回域字节的副本。

原生 P-256 Session 身份是其规范 Neo 标准账户脚本哈希的域，与 NeoNativeVerifier 共享。在两个 Session 之间、或在 Session 与其标准账户见证之间复用同一个 P-256 密钥，不能提供两票。所有未来原生 P-256 配置档都必须使用这一规范身份。无法从不透明的脚本哈希推断任意脚本或多签所有权；公开域不证明私钥/操作者独立性。旧版公开配置档是独立的策略与迁移边界。

签名字段是对确切 Array 的规范 Neo 二进制序列化，每个已配置子级对应一个元素。每个元素是 Null（跳过该子级）或该子级签名格式的 ByteString。原生见证子级使用空 ByteString 参与；它仍然需要其真实交易见证。子级接收原始六个操作字段，仅签名元素被替换。它们保留原生账户授权域。

例如，双子级捆绑 `[ByteString(signature), ByteString(empty)]` 同时请求签名验证器与原生见证验证器；`[Null, ByteString(empty)]` 只请求第二个。二选二策略即使在提供的唯一见证有效时也会拒绝后者。

## 瞬态批准回执与后置策略

校验在考虑法定人数之前检查每个签名槽的类型。它按配置顺序遍历子级，跳过 Null 槽，并在取得前 `threshold` 个确切 Boolean 批准后停止。它返回确切的 Array `[true, orderedApprovedChildren, policyCommitment32]`。原生合约严格检查形状与有序子集，深拷贝它，并仅为该一次操作保留。它绝不被持久化、从交易接受，或在 Verification 与 Application 之间共享。批量操作各自创建新鲜回执。任何交易提供的回执都不能创建模块授权。

后置回调接收原始操作/结果与该私有回执的新鲜副本。它首先重新加载配置与全部子级域，并比较其承诺。只有已批准的子级按配置顺序获得后置授权与回调。之后提供的有效签名不属于所选法定人数，也不消耗 Session 配额。根在全部子级回调之后再次重新加载配置与域；承诺发生变化会使该操作失败。原生合约还会检查当前代码固定值。

后置执行只跳过重复的密码学操作签名工作。每个 Session 重新检查其密钥处于活动、未过期状态，并允许确切目标/方法，然后应用结果/来源/金额与累计上限规则。每个 NeoNative 子级重新检查其交易见证法定人数，因为仅其签名方域并不承诺其内部阈值。账户、帧、阶段与当前权威代次检查仍然强制。

一个密码学无效但形状良好的签名，若返回 Boolean false，可以被跳过以采用后续子级。可捕获的子级异常同样视为拒绝。致命的 VM ASSERT/ABORT 或继承预算耗尽不是可恢复的投票；调用方必须使用 Null 来省略过期或不适用的子级。格式错误的未使用槽仍然拒绝。任何拒绝都会丢弃 nonce、目标与策略写入。每个根回调与所有后代共享不变的 1 GAS 预算；交易费用额度不会增加它。见证验证也仍受全局 1.5 GAS 限制约束。

## 依赖所有权与清理

托管方在根通过延迟 `callVerifier` 激活名册之前，通过延迟 `callVerifierChild` 操作配置叶子。原生合约拥有已登记/活动依赖记录、代码身份与清理顺序。根的 `clearAccount` 需要清理授权，检查原生依赖清理操作并移除根配置。它不得冒充叶子的清理或配置授权。移除/替换根必须清理已登记的叶子（包括已配置但未激活的叶子），并保留其他账户。这一普通配置清理与托管恢复不同。ABI 2 恢复推进 authorityEpoch 与 configurationNonce，清除根/依赖绑定与待定意图且不调用外部回调，并保留冻结状态与目标 nonce。旧模块状态变为不可达；恢复不需要已删除、已变更或失败的子级配合。

## 必需的证据

两次构建原始编译器输出，在不重写 NEF 的前提下打包能力，然后在一次性 NeoExpress 链上回读所有已部署字节。测试实际互不相同的原生见证与 P-256 签名、两个阶段、缺失或错误见证、规范捆绑解析、重复域、延迟子级/根配置、后置策略失败、nonce/资产/存储回滚与清理。在新的工件集上运行既有的五配置档回归。仅宿主的合成或未签名调用必须与持久化交易分开标识。本验证不包含任何 TestNet/MainNet 操作。

这些检查不证明原语密码学、任意未来插件行为、完整 NeoVM 语义或编译器精化。原生配置档不会仅因源码检查或编译通过就被认为已验证。

## 抽象阶段义务

形式化门禁必须区分校验与后置授权，拒绝错误的账户/模块/帧/阶段组合，建模新鲜的按操作局部回执，并拒绝格式错误或无序的已批准子集。只有确切的 Boolean 子级批准才计入首个法定人数。前置/后置承诺保留有序的按子级策略边界。这些是抽象义务；实际的原生授权、编译后分派、密码学与子级策略需要独立的运行时对应关系。

## 操作参数隔离

每次子级调用都必须接收对同一原始操作参数的独立深度物化。`ReadOnly` 调用标志约束持久化影响；它们不确立对 VM Array 或其嵌套值的所有权。子级不得改变后续校验、重新校验或后置执行回调所见的参数。快照必须在首次子级调用之前捕获，而不是在子级之间从可能已被修改的对象重新创建。只有每个子级的签名可以不同。反序列化失败即失败关闭。

回归测试必须使用一个会修改参数的诊断子级，后接一个诚实的签名验证器，包括嵌套参数值与正向对照。同一参数/结果隔离不变量适用于普通组合配置档。ABI 2 另行改变原生签名域与存储命名空间；副本隔离不得引入进一步的操作或预算变更。序列化与按子级重建消耗既有回调预算；在宣称验证通过之前，必须在私有链执行中测量其成本。每个子级后置回调还必须接收原始目标结果的独立深度快照，包括嵌套集合；快照必须在任何回调能够修改它们之前捕获。不支持的结果类型失败关闭。这一独立的结果隔离义务需要真实的修改型子级回归，且不能由参数复制测试确立。
