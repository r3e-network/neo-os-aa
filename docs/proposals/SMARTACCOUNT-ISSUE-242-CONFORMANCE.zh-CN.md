# 原生 SmartAccount issue 242 符合性映射

评审基线：2026-10-09；权威准入更正：2026-10-14。本映射遵循 [issue #242](https://github.com/neo-project/proposals/issues/242)，包括其六个必需章节与六条验收标准。它描述的是草案评审候选，而不是已采纳的标准，也不是激活公共网络的许可。

规范文档是[原生 ABI 2 配置档](SMARTACCOUNT-NATIVE-PROFILE-DRAFT.md)与[部署无关基础](nep-smartaccount-entry-verifier.mediawiki)。身份派生仍为版本 1。权威准入现在要求接收方同意，并拒绝已注册代理权威。这在不变更 ABI 方法、状态布局、身份派生或参数常量的前提下改变了草案共识行为。未变更的参数摘要不能标识该源码修订，也不能证明与早期实验状态的兼容性。

该基础支持并行的普通合约实现与原生实现。普通实现可以验证共享协议行为，并在其自身部署配置档下服务应用。本映射专门评估原生配置档；其共识激活、VM 强制回调预算与见证限制不能从普通合约执行中推断。

## 验收标准与证据限制

1. **规范状态与状态转换：** 配置档规定了账户记录与所有当前入口点。跨仓库审计把全部 **39 个方法与 16 个事件**（包括有序参数名/类型、返回类型与 safe 标志）与 core 匹配。发现过程必须拒绝缺失或格式错误的必需成员，而不是仅从摘要推断兼容性。
2. **规范向量：** [参数文件](smartaccount-native-profile-v2-parameters.json)、[向量文件](smartaccount-native-profile-v2-vectors.json)与验证器覆盖原生身份、地址、nonce、授权与见证编码。既有的 C# 与 JavaScript 检查是实现证据；它们不确立两个独立维护的共识客户端都接受。
3. **资源与费用：** 固定验证器/钩子上限、祖先计费、白名单行为、耗尽与交易费用影响都被规定。私有执行与预检回执仍钉在其实际源码/工件版本上；之后的仅测试或文档变更不会重写这些回执。
4. **权威、治理、恢复与迁移：** 账户级控制不能升级原生合约。公共激活与任何状态转换都需要显式的网络治理。登记原生身份会让旧版资产仍处于其原始见证规则之下。
5. **跨客户端与失败符合性：** §14 规定了必需的向量与回滚用例。新的时钟测试覆盖相等、一毫秒过期、缺失账本头、单笔/批量代理验证，以及在连续 Application 时刻的相同已签名字节。不主张完整的独立客户端符合性、完整编译器/VM 精化或任意第三方模块正确性。
6. **兼容性：** [#218](https://github.com/neo-project/proposals/pull/218) 是通用见证提案；[#243](https://github.com/neo-project/proposals/pull/243) 是部署无关基础；#242 新增原生身份、状态、资源与治理。已关闭的提案 [#219](https://github.com/neo-project/proposals/pull/219) 与 [#220](https://github.com/neo-project/proposals/pull/220) 描述可选扩展，不是已采纳的依赖。原生代理是见证机制的更窄配置档，而不是这些层的合并。

## 本次评审产生的更正

- 澄清强制的标量兼容性描述符与组合回调分派，同时不削弱模块准入。
- 定义链毫秒、持久化时间/执行时间之分、含端点的截止/成熟边界，以及缺失账本头时的失败关闭行为。
- 移除关于原生旧版导入或自动 ABI 1 状态转换存在的暗示。
- 把协议评审完备性与公共激活批准分离。
- 在 SDK 发现期间校验完整的必需 ABI（包括事件），并在 REST 序列化中保留嵌套原生元数据。
- 把既有的原生目标结果序列化器与参数编码分开记录：受支持的 VM 类型、运行时大小/项边界、重复引用拒绝与原子失败。配置档 §9.4 解释当前行为，不变更 ABI 或参数摘要；它不会把这些实现限制指派给普通合约配置档。
- 对新引入的托管/恢复接收方要求准入见证，并在每个当前或待定权威槽中拒绝已注册代理。保留无需许可的成熟转换，并禁止会让第三方阻止未来登记的反向预留。
- 当前实现评审通过 [core #4768](https://github.com/neo-project/neo/pull/4768)、[RPC #1115](https://github.com/neo-project/neo-node/pull/1115) 与 [foundation #243](https://github.com/neo-project/proposals/pull/243) 协调。上游评审与公共激活门禁仍开放。历史 issue 评论与钉住的运行时回执描述其原始检查点，不得被理解为当前部署主张。

[2026-10-09 验证回执](../reports/sa-issue-242-conformance-20261009.json)记录了本次评审的源码固定值、新回归用例与验证计数。

## 生命周期与可用性后续

[协议审计回执](../reports/sa-native-protocol-review-20261009.json)跟踪随后的客户端与工作区评审。它把无需许可的账户级激活与托管授权的模块策略激活分离，把模块取消评审绑定到其确切的待定意图，并[账户指南](../NATIVE_ACCOUNT_USER_GUIDE.md)记录用户的权威与时序选择。

2026-10-14 的引擎审计确认，此前的规则允许一个原生账户的代理成为另一个账户的托管或恢复权威，而正常的已授权转换随后可能失败。精确的目标帧隔离会隐藏祖先的授权，而两个独立的原生权威通常无法共享所需的单账户封套。这些检查保持有效。

更正后的草案从每个当前与待定托管/恢复槽中排除已注册原生代理，并对新引入的非零权威地址要求见证。原生候选在共同状态边界上应用这一点：`SmartAccountState.GetAuthorityAddresses` 同时包含当前与两个待定角色；`SmartAccount.ReadState` 校验已注册代理排除；`Save` 比较完整的下一/先前权威集，并在写入之前校验准入。登记同样在外部模块发现之前检查准入。普通钱包、CHECKMULTISIG 与已部署合约权威按其实际原生见证规则仍具资格。

携带恢复的创建现在需要两个接收方同意；提名需要新接收方同意，以及既有的托管或恢复发起方。成熟激活与托管恢复执行仍无需许可，因为目标已在其待定记录中被准入。不引入反向预留索引：第三方不能通过把未来账户的预计算地址命名为恢复来阻止其确定性登记。未来未注册的代理无法提供有效的规范交易见证，而已存在的代理被显式拒绝。存储的无效权威会失败关闭；本草案不会静默修复先前的实验记录，也不提供其迁移。

这些变更解决了候选的已记录准入策略；它们不确立普遍实现精化、独立客户端符合性、上游采纳或公共激活。运行时主张必须继续绑定到更正后的候选及其回归证据，而不是上文链接的历史回执。

[可用性后续](../reports/sa-native-usability-20261009.md)为 SDK 取消、标准 Neo CHECKMULTISIG 钱包权威、确切签名文件提交与历史回执恢复增加了执行时待定内容检查。这些是客户端与集成保证；原生两参数取消入口点、ABI 2、身份版本 1 与参数摘要保持不变。本次后续中的原生 core 新增内容是测试。

[性能比较](../NATIVE_ACCOUNT_PERFORMANCE.md)保留全部回调上限与授权检查。新的自有范围副本把所测量最大 fixture 的后置执行回调成本降低 239,646 datoshi（0.2504%）。该结果特定于钉住的运行时与模块工件；它不确立网络吞吐、任意模块可行性或编译器精化。那些历史结果早于上文的权威准入更正，不能替代其回归证据、独立共识客户端符合性或上游协议评审。
